1부 · AI 수업 기본기 · 3차시

구조화 출력

"JSON으로 답해줘"는 90%쯤 통한다. 나머지 10%가 프로그램을 멈춘다. 형식은 부탁이 아니라 강제해야 한다.

핵심 정리

신뢰도 4단계

단계방법보장하는 것
1프롬프트로 부탁없음 (약 90%만 성공)
2JSON 모드JSON 문법은 맞지만 칸 이름·종류는 보장 안 함
3스키마 모드정해 둔 칸 이름·종류·조건을 지킴
4제약 디코딩글자를 고르는 순간 틀린 글자를 막아 100% 지킴
  • JSON 스키마가 계약서 역할을 한다. 예를 들어 "price": {"type":"number","minimum":0}는 음수 가격을 막는다. OpenAI·Anthropic·Gemini가 모두 쓴다.
  • 제약 디코딩 — {"price":까지 썼다면 다음엔 숫자·따옴표·null 같은 것만 허용하고 나머지 글자의 확률을 0으로 만든다. 이건 프롬프트 문제가 아니라 글자 선택(디코딩) 문제다.
  • 파이썬에선 Pydantic 모델로 스키마를 자동으로 만든다. Instructor 같은 도구는 결과를 검사하고 틀리면 오류를 알려 주며 다시 시킨다.
  • Anthropic의 도구 사용, OpenAI의 함수 호출도 사실상 구조화 출력이다.

자주 나는 실패

  • 그럴듯한 가짜 값 — 형식은 맞는데 내용을 지어낸다 (본문엔 348달러인데 299.99달러로 씀). 형식 검사로는 못 잡는다.
  • 허용 목록에 없는 비슷한 값을 쓴다.
  • 중첩이 4단계 넘게 깊어지면 오류가 급격히 는다.
  • 개수 조건(최소·최대 개수)을 어긴다.
  • 선택 칸은 빼 버린다. 필수로 두고 없으면 null을 쓰게 하는 게 낫다.

코드가 하는 일

  1. 파이썬 값이 스키마에 맞는지 재귀적으로 검사하고 틀린 곳을 모두 모은다.
  2. 파이썬 클래스 정의를 JSON 스키마로 바꾼다.
  3. 쓰다 만 JSON을 보고 다음에 올 수 있는 글자 종류를 계산한다 (제약 디코딩 흉내).
  4. 상품 설명에서 정보를 뽑아 → JSON 해석 → 검사 → 틀리면 최대 3번 다시 시키는 파이프라인.

선생님께 적용

스킬 — 스킬 결과를 다른 단계(PPT 생성, HWPX 채우기)로 넘길 땐 "이 칸들을 이 형식으로"를 표나 JSON 틀로 명시한다. 선택 칸은 "없으면 빈칸이라고 쓸 것"처럼 필수로 바꾼다.

수업 — 성인 과정에서 "영수증 사진 → 날짜/가게/금액 표로" 실습을 하면 구조화 출력과 가짜 값 문제를 함께 보여줄 수 있다. 결과를 원본과 대조하는 습관까지 연결한다.

직접 해볼 것

  1. 아래 프롬프트를 넣고, 결과 JSON의 값이 본문과 정확히 같은지 하나씩 대조한다.
아래 글에서 정보를 뽑아 JSON 하나만 출력해줘. 설명이나 코드 블록 표시 없이 JSON만. 칸: name(문자열), price_won(숫자), in_stock(true/false), colors(문자열 목록), warranty_years(숫자, 없으면 null) 글: 새로 나온 무선 이어폰 '소리온 미니'는 89,000원이다. 화이트와 네이비 두 가지 색이 있고, 네이비는 현재 품절이다. 충전 케이스 포함.
  1. 같은 글로 "JSON으로 정리해줘"만 넣어 보고, 칸 이름이 매번 달라지는지 비교한다.
