3부 · 스킬 제대로 만들기 · 10차시

스킬 발견과 단계적 공개

스킬은 세 번에 나눠 보여준다. 목록엔 이름과 설명만, 켜지면 본문, 필요할 때만 참고 파일.

핵심 정리

단계적 공개 3단계

단계내용기준
1. 목록이름 + 설명항목당 약 100토큰. 설명은 "무엇을 한다 + 언제 쓴다" 두 마디로
2. 본문SKILL.md 본문약 500줄 이하. 작업 범위, 순서, 분기 조건, 참고 파일 위치, 멈출 때
3. 자원references, scripts, assets참고 문서는 설명, 스크립트는 정해진 계산, 자산은 틀·예제 (지시문 아님)
  • 목록 비용과 본문 비용은 따로 계산한다. 설명을 줄여도, 켜진 뒤 900줄 본문은 그대로 창을 차지한다.
  • 원문 기준 Codex는 처음 스킬 목록에 창의 2%를 쓴다 (모를 땐 8,000자).
  • 참고 파일은 주제 덩어리보다 분기별이 낫다. "파이썬이면 references/python-release.md를 읽어라"처럼 언제 읽을지가 드러나야 한다.
  • 본문을 짧게 보이려고 핵심 절차까지 참고 파일로 빼면, 켜졌을 때 정작 필요한 내용이 없다.

발견과 충돌

  • 찾는 위치는 여러 겹이다 — 작업 폴더, 사용자, 관리자, 플러그인, 기본 내장.
  • 같은 이름 스킬이 두 곳에 있을 수 있다. 목록 항목엔 이름·설명·위치·출처 경로·선택 여부를 함께 둔다. 어떤 규칙으로 이길지 미리 정해야 한다.
  • "내 스킬을 안 써요" 문제를 풀려면 어디를 찾았고, 무엇을 거절했고, 무엇이 이겼는지 기록이 있어야 한다.
경로 검사를 글자 앞부분 비교로 하면 references/../../../../.ssh/config 같은 경로에 뚫린다. 실제 경로로 풀어서 스킬 폴더 안에 있는지 확인해야 한다.

코드가 하는 일

  1. 위치(범위)마다 바로 아래 폴더에서 SKILL.md를 찾는다. 더 깊이는 안 본다 (예제 폴더가 잘못 공개되는 걸 막음).
  2. 정해진 우선순위로 이름 충돌을 해결하고, 가려진 후보도 보고서에 남긴다.
  3. 예산 안에서 목록을 만든다.
  4. 스킬을 켜면 본문을 읽고, 참고 파일은 경로가 폴더 안인지 확인한 뒤 크기 제한을 두고 읽는다.
  5. 읽을 때마다 스킬 이름, 파일 경로, 이유, 바이트 수를 기록한다.

선생님께 적용

스킬 다이어트 — 긴 스킬(예: 워크북, HWPX)은 본문에 "항상 필요한 순서"만 남기고, 경우별 세부(시험지 형식, 공문 규칙 등)는 references로 나눈 뒤 본문에 "이 경우엔 이 파일을 읽어라"를 적는다.

설명 다듬기 — 목록엔 설명만 보이므로, 비슷한 스킬끼리(예: hangeul-doc vs gongmun-hwpx vs hwpx-yangsik-fill) 경계가 설명에 분명히 드러나야 한다.

직접 해볼 것

  1. 가장 긴 스킬 하나를 골라 아래로 나누는 안을 받아 본다.
아래 SKILL.md를 단계적 공개 원칙으로 재구성하는 안을 만들어줘. - 본문에 남길 것: 매번 필요한 순서와 판단 - references로 뺄 것: 경우별 세부. 파일 이름과 '언제 읽는지' 조건을 함께 - 본문을 짧게 하려고 핵심 절차를 빼지는 말 것 지금 본문 줄 수와 재구성 후 예상 줄 수도 알려줘. [SKILL.md 붙여넣기]
