2부 · 에이전트가 도는 원리 · 8차시

에이전트 루프

모든 에이전트는 같은 고리를 돈다. 관찰 → 생각 → 행동 → 관찰. 프레임워크는 그 고리 둘레의 장식이다.

핵심 정리

  • Claude Agent SDK, Cursor, Devin 같은 에이전트는 모두 2022년 ReAct(추론 + 행동) 고리의 변형이다.
  • 언어 모델만으로는 사실 확인, 파일 읽기, 잘못 고치기를 못 한다. 도구 결과로 땅에 발을 붙이는 게 ReAct다. 원문 기준 ALFWorld +34점, WebShop +10점.
  • 2026년 변화 — 예전엔 Thought:를 글로 쓰게 했지만 지금은 모델 내부 추론 채널로 분리된다. 고리 자체는 그대로다.

에이전트의 필수 재료 5가지

  1. 메시지 버퍼 — 사용자, 모델, 도구 결과가 차례로 쌓인다.
  2. 도구 등록부 — 이름과 실행 함수, 입력 검사.
  3. 멈춤 조건 — 완료 선언, 도구 호출 없음, 최대 턴 초과, 토큰 소진, 안전장치 작동.
  4. 턴 예산 — 반복 한도. 원문 기준 요즘은 작업당 40~400단계도 보통이다.
  5. 관찰 정리기 — 오류(400 등)까지 포함해 모든 도구 결과를 읽을 수 있는 글로 바꾼다.

핵심 고리 (의사 코드)

def run(query, tools):
    history = [user(query)]
    for step in range(MAX_STEPS):
        msg = llm(history)
        if msg.tool_calls:
            for call in msg.tool_calls:
                result = tools[call.name](**call.args)
                history.append(tool_result(call.id, result))
            continue
        return msg.content
    raise StepLimitExceeded

원문 README에 실린 예시. 도구를 부르면 결과를 붙이고 다시 돌고, 도구 없이 답하면 끝난다.

2026년의 함정

  • 신뢰 경계 붕괴 — 도구 결과는 믿을 수 없는 입력이다. 악성 PDF나 검색 결과 속 지시가 모델을 조종할 수 있다.
  • 연쇄 실패 — 잘못된 값 하나가 뒤 단계로 번진다. 400 오류를 받고도 성공했다고 지어내기도 한다.
  • 긴 고리 — 38번째 단계 오류를 찾으려면 기록(트레이스)이 필요하다.

코드가 하는 일

  1. ToolRegistry — 이름과 실행 함수 연결, 입력 검사.
  2. ToyLLM — 인터넷 없이 시험하도록 Thought/Action/Observation/Finish 줄을 정해진 대로 내놓는 가짜 모델.
  3. AgentLoop — 버퍼를 프롬프트로 → 모델 호출 → 도구 호출 해석 → 실행 → 결과 수집 → 멈춤 조건 확인 → 반복.
  4. 예시 도구 — 계산기, 키-값 저장소 읽기·쓰기. 표준 라이브러리만, 200줄 이내.

python3 code/main.py를 돌리면 생각·도구 호출·관찰·최종 답이 순서대로 찍힌다.

선생님께 적용

수업 — 파이썬 고급반·성인 과정에서 이 20줄 남짓한 고리를 칠판에 그리면 "AI 에이전트"가 마법이 아니라 반복문이라는 걸 보여줄 수 있다. 가짜 모델(ToyLLM) 방식이라 API 키 없이 수업 가능하다.

Claude 작업 이해 — Claude가 파일을 만들고 렌더해서 확인하는 과정도 이 고리다. 결과를 눈으로 확인하는 단계(관찰)를 요구하는 선생님의 검증 원칙이 연쇄 실패를 막는 장치다.
