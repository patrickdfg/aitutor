함수 호출과 도구 사용

모델은 뇌, 도구는 손, 함수 호출은 둘을 잇는 신경이다. 모델은 무엇을 부를지 정하고, 부를지 말지와 실행은 프로그램이 정한다.

핵심 정리

5단계 흐름

  1. 사용자가 메시지를 보낸다.
  2. 모델이 메시지와 도구 정의(JSON 스키마)를 함께 받는다.
  3. 모델이 함수 이름과 인자를 구조화해서 내놓는다.
  4. 프로그램이 함수를 실행한다.
  5. 결과를 모델에게 돌려주면 모델이 최종 답을 정리한다.

병렬 호출과 오류 처리

  • "도쿄와 뉴욕 날씨?"처럼 서로 독립인 호출은 한 번에 여러 개 나온다. 왕복이 2번에서 1번으로 줄어 원문 기준 지연이 60~80% 준다.
  • 도구가 실패하면 예외를 던지지 말고 구조화된 오류를 돌려준다. {"error":true,"message":"'Toky' 도시를 못 찾음. 'Tokyo'인가요?"}처럼 구체적이면 모델이 스스로 고친다. 빈 응답이나 막연한 오류로는 회복을 못 한다.
  • 도구 설명 자체가 모델에게 주는 프롬프트다. 설명이 흐리면 엉뚱한 도구를 고른다.

보안 5원칙

  1. 모델이 만든 SQL을 그대로 실행하지 않는다.
  2. 필요한 함수만 노출한다. "이름으로 아무 함수나 실행"은 금지.
  3. 실행 전에 인자를 검사한다. 도시 이름 칸에 "; DROP TABLE users; --"가 들어올 수 있다.
  4. 결과에서 API 키·개인정보·오류 내역을 걸러서 돌려준다.
  5. 대화당 도구 호출 수를 10~20회로 제한한다.
도구 결과 안에 "이전 지시를 무시하고…" 같은 문장을 심는 공격(도구 오염)이 있다. 도구 결과는 정보일 뿐 명령이 아니다.

코드가 하는 일

  • 도구 5개 — 계산기(안전한 연산자만), 날씨(가짜 데이터, 오타 제안), 웹 검색(가짜), 파일 읽기(.. 차단·허용 목록), 코드 실행(구문 트리로 import 등 차단, 교육용 수준).
  • 인자 검사 — 필수 칸, 종류, 허용 목록, 모르는 칸 거부.
  • 실행 루프 — 결정 → 검사 → 실행 → 결과를 기록에 추가 → 반복, 기본 5회 제한.

제공사별로 이름만 조금 다르다. Anthropic은 input_schema, OpenAI는 parameters를 쓰고, OpenAI는 결과를 돌려줄 때 tool_call_id를 맞춰야 한다.

선생님께 적용

스킬 — 스킬 안의 스크립트가 실패할 때 "무엇이 왜 실패했고 무엇을 확인하라"를 출력하게 만들면 Claude가 스스로 고친다. 빈 출력이나 긴 오류 전문보다 짧고 구체적인 한 줄이 낫다.

수업 — 파이썬 수업 고급반에서 이 레슨의 계산기·날씨 도구 구조를 그대로 따라 짜게 하면 "AI가 도구를 쓴다"를 코드로 보여줄 수 있다.
